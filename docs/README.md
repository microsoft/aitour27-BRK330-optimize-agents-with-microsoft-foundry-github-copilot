# Docs

> Reference material supporting the attendee and presenter workflows. This is useful reading only if you plan to reproduce the demos from scratch (note: your outcomes may vary).

| Document | Purpose |
|---|---|
| [`session-source-of-truth.md`](session-source-of-truth.md) | Approved session narrative, demo contracts, evaluation contract, and readiness plan. |
| [`technology-status.md`](technology-status.md) | Date-stamped lifecycle status and demo usage for Foundry/Copilot capabilities. |
| [`troubleshooting.md`](troubleshooting.md) | Verified failure modes, Agent Insights prerequisites, RBAC scope guidance, and repeatable recovery checks. |

> **Where you are:** `docs/` contains supporting context and troubleshooting. Speakers should start in [`delivery-resources/`](../delivery-resources/README.md), choose the recorded-demo or live-reproduction path, and return here when they need deeper reference material.

The core folders to know are:

1. **Deliver the session** - start under [`../delivery-resources/`](../delivery-resources/README.md).
2. **Reproduce the demo** - follow [`../instructions/`](../instructions/README.md).
3. **Set up infrastructure and RBAC** - use the numbered scripts under [`../infra/`](../infra/README.md).
4. **Review measured evidence** - inspect evaluation and training artifacts under [`../data/`](../data/README.md).
